# Future governed creative comparison — proposal only

Mission17 does not authorise provider activation, inference, spending, hosted installation, automatic saving or publication. This document is an evaluation proposal, not an approval packet, reservation or proof of provider readiness.

## What the current contract can test

The existing `busy.website-art-direction.v3` comparison fixes its review scope to **Home**. A validated proposal can select existing composition families, whole-page direction, permitted service/process presentation, at most two eligible Home section moves, mobile spacing and supported contact/menu emphasis. Its copy choices are only `unchanged` and the exact approved `profile-introduction`.

Shared theme choices may affect inner-page presentation, so the resulting complete site should be inspected. However, v3 cannot plan page count, create routes, redesign navigation hierarchy, choose new Mission17 presentation metadata or generate original service/story copy. No such authority should be inferred from a successful schema check.

## Proposed first real experiment

- Use one reviewed, fictional, image-free **Quiet Light Studio** source, frozen after Mission17 verification. Both candidates start from the same approved facts, words, branding, destinations and reviewed whole-site model.
- Candidate A uses the existing deterministic recommendation. Candidate B uses one genuine model response through the separate server-owned provider adapter, never the zero-usage offline-fixture callback.
- Limit the proposed request to **4,000 input tokens, 1,000 output tokens and £0.10 maximum total admitted exposure**. These limits do not authorise spending.
- Prohibit tools, executable HTML/CSS/JavaScript, invented business facts, retries, fallback, external actions, automatic account saves and publication.
- Validate the response against the original schema, current source identities/revisions, protected wording and supported finite operations. The original Website Studio remains the sole consequential save authority after a separate deliberate review.

Before dispatch, independently verify the exact model/provider and intended account access, structured-output support, exact or conservatively enforced token limits, current applicable tariff and all-in GBP ceiling. Freeze the complete input/schema/wire digests. Obtain a fresh one-use owner execution/spending approval and authoritative central budget reservation with independent readback. Missing, stale or uncertain evidence means **no dispatch**. No current model availability, tariff, entitlement, reservation or approval is claimed here.

Retain a real provider request receipt, exact returned model and actual usage/cost reconciliation, including invalid or aesthetically inferior outputs. A timeout, missing response or lost acknowledgement must retain uncertainty/liability and must not trigger a second dispatch. Offline fixtures remain explicitly labelled fixtures.

## Review method and useful next questions

Render both candidates through the same original renderer and source-held capabilities. Use opaque candidate labels where practical. Review complete mobile and desktop Home, service, About and contact journeys for coherence, individuality, typography, useful hierarchy, truthful messaging and owner desirability. Record specific strengths and weaknesses; choose no automatic winner or numerical beauty score. Source/technical correctness remains separate from professional visual judgement and explicit owner acceptance.

One request can establish feasibility and offer early qualitative evidence. It cannot prove reliable superiority, multi-page economics or exceptional quality across businesses.

The most valuable later AI questions are which visitor information deserves prominence, whether a page adds distinct value, which source facts support a service explanation, and which single missing owner detail would materially improve the result. True whole-site planning or new grounded-copy proposals require a separately versioned schema, source/permission review and bounded evaluation. They are **not** extensions silently granted to v3. No additional adapter or infrastructure expansion is proposed by this document.
