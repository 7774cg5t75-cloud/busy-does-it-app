# V3.129 — Separate staging cost decision, real Auth and fictional hosted previews

## What was delivered — no cloud provisioning

**Do not mistake V3.129 source artifacts for a launched staging environment.** The code is committed on the `v3.129` branch, not merged to production. The special CI builds two genuinely BUSY-generated fictional website designs (Hillside Gardens and Fire & Table Catering), packages their exact HTML and SHA-256 fingerprints into a deployable Cloudflare Worker module, then tests the authorization and website rendering without connecting to a real external service. The worker is NOT deployed.

`staging/fictional-hosted-preview-worker-v3129.mjs` allows exactly two known fictional previews from the generated bundle. Each view must have a valid bearer access token. The Worker queries the **dedicated staging Supabase** `GET /auth/v1/user` using the public staging API key on **every page request**, and compares the verified identity to the configured fictional owner ID. A caller-supplied business/role header is ignored. Cross-owner reads return 404. Missing/invalid bearer returns 401 or denial. HTTP mutations return 405. The source SHA, stage hostname, staging project reference and both separate protected Supabase project references must match the reviewed environment; production or Slow Roast references are rejected. Files have noindex/no-store and restrictive CSP headers; these are fictional HTML with no scripts or external resources.

`scripts/build-fictional-hosted-bundle-v3129.mjs` takes the existing BUSY website design gallery output, builds a `staging/generated/preview-worker.mjs` deployable module and a manifest, and records that it **has not been published**. Source hash and generation are pinned. The dedicated GitHub Actions workflow `.github/workflows/staging-fictional-hosted-v3129.yml` runs tests and saves fictional, credential-free artifacts for seven days. These artifacts require explicit staging-host deployment approval before any public HTTPS serving.

## Connected account and cost facts, checked 10 October 2026

- The connected Supabase organization `Busy does it app` is on the Free plan. Its two active projects are Busy Does It and Slow Roast. The Free plan limits active projects to **two** across owner/admin organizations; do not rely on the connector's `$0/month` Free-organization create-project quote to mean a third project is allowed.
- Published Supabase Pro organization base subscription: **$25 USD/month**. Default Micro compute for paid projects: approximately **$10 USD/month per running project**, billed hourly, and the organization receives **$10/month in compute credit**. If this one organization is upgraded to Pro and all **three** projects run as Micro, an illustrative steady-state total is **$25 + $30 - $10 = $45 USD/month**, excluding usage-based overage, extras and VAT/exchange fees. Upgrading can also change compute charges for the existing two projects. Obtain the *actual on-account billing screen quote* and explicit founder approval before any upgrade or creation.
- Cloudflare Workers Free provides up to **100,000 requests/day** with CPU restrictions, and may be sufficient for small fictional testing without upgrading the account. Workers Paid minimum is **$5 USD/month** if chosen/required. Zone/route and DNS setup depend on the actual Cloudflare account configuration; don't claim a zero-cost deployment before confirming limits and current plan.
- Supabase development branches are an alternative to a new project but are available with paid-plan branching and **branching compute is not protected by the Spend Cap**. The project approach is preferred here for transparent long-lived staging and no automatic production migration coupling.
- Reserve `staging.busydoesit.co.uk` as the intended hostname **only after verifying it is unused** and that it cannot collide with production or customer website routing. Do not edit DNS or Cloudflare Workers without explicit authorization.
- No provider settings, plan upgrades, paid project, Supabase branch, Cloudflare Worker, DNS record, staging users, JWTs or EAS signed iOS build were created in this sweep.
