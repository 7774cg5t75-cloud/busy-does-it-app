# Prepare → Verify → Approve → Execute → Independently Verify

This permanent method grants no operational authority. The timing-v2 implementation
is a local review candidate until exact owner policy/source approval. Original
private Word masters have not been reconstructed or updated here.

## Finish the actual path before requesting authority

1. **Prepare:** freeze the source, schema, renderer, dependency graph, upload,
   management bindings, durable intent, result route and protected workflow.
   Transfer/hash the large static upload before short-lived facts. Preloading
   grants no submission, credential or provider capability. Reuse original owners.
2. **Verify:** rehearse the real prepared path with explicit fake management and
   provider ports: slow responses, expiry, changed bytes, cache loss, durability,
   failed readback, unknown acknowledgement and replay. Separate these results
   from genuine native observations, GitHub CI and hosted inference.
3. **Approve:** present exact policy/code/artifact hashes, target, one-use scope,
   costs, original deadlines and limitations. Artifact acceptance, conditional D,
   deployment, credential binding, queue and paid-run release are distinct powers.
   Consolidation must name each permitted phase; vague preparation grants no D.
4. **Execute:** require genuine unexpired owner authority. Admit sufficient time
   and critical freshness headroom before intent. Immediately before the external
   call recheck actual time, exact payload/hash, target and typed conditions with
   no asynchronous gap. Unknown submission is inspect-only, never replayable.
5. **Independently verify:** retain raw responses before normalisation. Check
   runtime bytes/imports, native function/version/bundle, JWT and unchanged data,
   security and financial state. Incomplete readback blocks later credentials and
   spending. A shell exit zero alone does not establish success.

## Typed evidence and safe ordering

Large payload transfer, tool setup and heavy DB observations precede final cheap
target checks. Timing-v2 permits exactly bound read-only financial/security facts
before C2 consent only while they remain inside the five-minute critical age and
required pre-intent headroom. Immutable source/public commit/tree and review facts
may precede consent within fifteen minutes. Neither supplies action authority:
owner consent to the exact already frozen packet is required before intent.

Project/organisation/function and credential absence remain post-consent. Collect
them last. Use supported names-only native absence evidence or an explicit accurate
owner statement in exact C2 consent. Never retrieve a credential value or invent
an API timestamp. The statement's genuine first observation/issuance clock matters;
recording it later must not refresh it. Reuse valid evidence; if genuinely expired,
obtain new evidence instead of silently changing a timestamp.

Immediately before intent reject insufficient measured freshness, execution time
or missing preloaded payload without consuming allowance. After intent repeat the
actual before-call checks. Preserve intent after every failed/uncertain outcome.
Full post-deployment database/security equality is required before key binding.
