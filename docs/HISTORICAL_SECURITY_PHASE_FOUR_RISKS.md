# Phase Four retained risks and continuation order

This extends the historical audit coverage/risk record; it is not a release certification. Prior Phase One–Three findings and negative tests remain applicable.

1. **Provider activation blocked:** canonical finite metadata and intent preparation now reach the original signed-in application, but real exchange, provider-subject proof, secure persistent PKCE, key-managed credential encryption, rotation, remote revocation and retention are not accepted. Calendar remains source-blocked. All legacy provider denial fences stay intact. Treat this as a high-impact activation dependency, not an exposed newly live credential feature.
2. **Public activation blocked:** atomic original challenge quotas and source-locked submit are source/local protections. Exact hosted migration inventory, grants, trusted proxy assumptions, infrastructure rate controls, business suspension semantics, guest erasure and real public/JWT acceptance remain unverified. Guessing IDs or rotating IP headers grants no protected identity. Fixed aggregate limits do not prevent distributed denial of service or prove fair use.
3. **Network acceptance incomplete:** custom-domain health fetches are denied pending a reviewed egress boundary. Denial returns unverified without outage/fallback changes; prior cached health is not fresh proof. Platform-owned destinations are allowlisted, but DNS/infrastructure ownership and broader worker/media/provider egress still require review.
4. **Dependency findings unresolved:** fresh registry audit is retained as a failure, not suppressed. Four advisory families remain: Zod oversized collection exhaustion, deepmerge object poisoning, glob cancellation/traversal and minimatch amplification. Lockfile is unchanged; affected-node propagation changes with registry metadata. Expo CLI/config/Metro/fingerprint are affected tooling paths; do not assume all native/dev-server/build reachability is harmless. Compatible remediation must be demonstrated before upgrading; forced major overrides/Expo downgrades are not accepted. No vulnerable library was newly introduced to the finite proposal runtime.
5. **Legacy social request hardening:** configured owner verification now precedes body consumption, and the original authenticated draft route rejects streamed inline-media requests over 8 MiB. Raw exception text is no longer logged. Larger original multi-photo requests must be reduced or await an approved bounded upload flow; no partial write is claimed. This does not establish canonical media ownership or safe multi-request upload transactions.
6. **Historical review incomplete:** original publication/private-media upload/message/push/outbox action coverage, effective hosted ACL/default grants, storage IAM, native secret handling and independent assurance remain outstanding. Ten direct-model paths stay denied; central cost admission externally disabled. No claim that every paid pathway is integrated.

Next substantial mission should continue **targeted security remediation**, not another repository inventory: finish original private-media ownership/upload transactions and remaining publication/message writer grants; establish provider credential/key lifecycle source contracts. Safe connected feature development can continue in parallel with those gates closed. Return to broad provider-dependent features only after these boundaries and authentic staging prerequisites are reconciled. No broad owner testing is requested yet.
