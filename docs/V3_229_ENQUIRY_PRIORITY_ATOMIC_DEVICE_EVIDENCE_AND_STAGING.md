## Concrete customer and backend improvements

1. **Open the RIGHT enquiry, not merely the newest.** The existing authenticated owner/admin queue now selects `received` requests first whenever at least one is new; only otherwise does it select `reviewing`. Stable second-order ID sorting removes same-time ambiguity. The shared queue classifier rejects mismatched latest-request status. BUSY's next action rejects missing/contradictory original receipt evidence. This fixes a situation where a recently updated reviewing request might be opened while BUSY told the owner to check a new request. No additional CRM or customer record.
2. **Stronger guest receipt tenant proof.** Guest `status` reads the actual mini-app row bound to both original app ID and business ID, and fails closed if the original business-owned app cannot be found. Original browser receipt remains required; statuses do not confirm appointments without corroborated source evidence.
3. **Atomic per-device notification evidence (new additive migration).** `20261014194500_v3_229_guest_alert_device_evidence.sql` creates a private, FORCE-RLS, service-role-only device-attempt table tied to the **existing** V3.226 original outbox. Each attempt records a keyed HMAC of the device token, recipient position, bounded Expo ticket ID where accepted, gateway result and `not_checked` device receipt status. It stores **no raw device token, customer details or message content**. A new security-invoker RPC validates an active V3.227 lease, writes bounded recipient statuses and completes the original outbox in the **same database transaction**; failure rolls back and expired leases remain manually quarantined, never blindly resent. Accepted gateway ticket is NOT proof of delivery to a device.
4. **Worker source properly wired but OFF.** The existing disabled Edge dispatcher maps each expected recipient's gateway ticket, verifies each device slot, HMACs tokens with its private worker secret and invokes the new atomic finalisation RPC. Mixed success/failure → uncertain/manual review, entire batch accepted only when every device ticket was accepted. Network timeouts, malformed results or missing devices do not grant false delivery/auto-retry. No cron, provider send, paid provider, Edge deployment or hosted database installation occurred.
5. **Safer staging dependency and phase-one review.** Updated all inherited staging inventories to **67 versioned migrations** plus the separate isolated business baseline. `prepare-phase-one-approval-v3229.mjs` produces a source SHA-256 review packet for the original two-table isolated business baseline, explicitly identifies pgcrypto/privilege review and prevents confusing the historical canary snapshot with live evidence. It provides NO executable installer or rollback, no implicit approval and no access to production data. The larger V3.228 source SHA inventory and earlier phase-readiness gates remain intact.
