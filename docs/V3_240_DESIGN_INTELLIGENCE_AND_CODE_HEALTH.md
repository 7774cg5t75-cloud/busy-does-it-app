# Busy Does It V3.240 — Contextual App Design, Responsive Reuse, Brand DNA and Code Health

## Objective
Turn generic design rules into more useful, explainable recommendations in the **existing** Business App Builder without inventing screenshots or working customer bookings. Retain V3.239's real local WebView reports across screen sizes and strengthen code health on the five-sweep checkpoint.

## Implementation
1. **App Builder goal-aware design** — \`appGoalDesignReviewV3240.mjs\` derives actual enabled customer-task status from \`taskReadiness\`, a finite private appearance proposal from \`prepareAppVisualBatch\`, and width-by-width static layout comparison using \`evaluateResponsiveApp\`. The review labels new warnings as **static advisories**, not measured breakages, and never promises customer task completion.
2. **Shared brand decisions** — reuse the original \`buildBusinessBrandDnaSnapshot\` on an exact same-business pair, producing only a simple brand agreement/owner-review notice (no copying business data into new logs or training).
3. **Simpler experience** — short, contextual text inside the App Builder's original optional screen-size explanation; existing owner approval remains untouched. No new complex screens.
4. **Website multi-screen continuity** — \`websiteCurrentCandidateV3240.mjs\` retrieves safe, source-bound original/candidate measures after phone/tablet/desktop switches, without replaying the wrong width's live state. Previously measured regressions still block keeping that private design. This is on-device WebView DOM evidence, not independent rendered screenshots.
5. **Code-health and regression** — new V3.240 focused tests and automated audit plus inherited production, PostgreSQL, website fictional Chromium screenshots and preview export.

## Safety boundaries and unfinished evidence
Only current same-tenant private drafts are eligible; public publishing, billing and bookings still require separate authority and verified outcomes. Screenshot evidence for the customer's particular app was not captured or certified in this sweep. Simulated iOS/Android widths and CI's fictional website images must not be represented as actual customer-device testing. No hosted SQL or paid native builds. Future work should connect approved native screen captures and real staging customer-task confirmations to the same grounded approval policy.

**North star:** the business owner gives BUSY an outcome and gets a useful, coherent, genuinely verifiable result, without unnecessary technical choices.
