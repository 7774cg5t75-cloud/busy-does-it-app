# Original media upload operation candidate

Undeployed, abort-fused subordinate contract for the existing authenticated private-original gateway. Install only in a disposable local fixture after the original business/membership, private media registry and private Storage metadata contracts. Production client and gateway flags remain false.

The gateway validates actual bytes, computes digest/MIME/length, authenticates through original Auth, then calls the service-only finite operation RPC. SQL independently requires the original current creator-owner/business membership. Client request keys/selection labels are idempotency context, never identity or permissions. Scalar fields only; no media blobs or arbitrary JSON writes.

New operations receive server UUIDs and a planned private path. PostgreSQL atomically finalises the original registry identity and operation, but cannot atomically commit Storage. A pending operation is reconciled only after the original gateway downloads and verifies the exact object. Missing objects remain pending; duplicate operation requests never re-authorise upload. Distinct keys may deliberately reuse an existing verified digest. Concurrent digest races may leave a known unreferenced object: no automatic deletion. Committed history and current asset eligibility are distinct.

A finalisation response may be an own-operation receipt. Independent inspection/discovery always returns notOwnReceipt, even if inspection completes an object-only pending record. Invalid pre-ingestion bytes can be explicitly rejected; missing operation rows alone are not proof that an in-flight request never started. The candidate records pending/committed operations, not a durable invalid-input ledger. Current private access is not copyright/customer promotional consent/provider permission.

Finite bounded cursor catalogue; technical candidate allowance60 new intents/owner/business/hour, serialised before creation. Duplicate-key observations do not consume a new intent. Effective raw-table and anonymous/authenticated RPC permissions deny; fixed privileged search path. Reapplication retains existing records. Rollback retains all objects/rows and exposes only reviewed service inspection/list, with no write access through the retained implementation. The rollback package is a one-time reviewed candidate, not an automatic hosted repair.

Local tests use real PostgreSQL17 metadata with synthetic Auth and inert Storage transport. They are not hosted JWT/PostgREST/Storage acceptance. Provisioning, credentials, rollout, retention/erasure, real Storage race/failure behaviour and native ownership acceptance require separate review. Legacy website-original upload/download and original publisher ownership remain separate; no queue insertion or publishing authority is added.
