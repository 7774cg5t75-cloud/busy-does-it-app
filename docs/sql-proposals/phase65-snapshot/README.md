# Phase65 — first Enquiry and first private reply, review only

This proposal is NOT a deployed migration. The Phase58 write fence, Phase60 privacy fence, Phase64 filing fuse and new Phase65 production abort fuse remain intact. Hosted switches remain false. Only the guarded local synthetic PostgreSQL runner strips exact known fuses for rehearsal. Do not apply to hosted staging or production without separate review/approval.

Original authority: Phase58 private original catalogue handoff and Phase59 exact invoker ensure/creator-trigger definitions. Reuses original snapshot row, membership-before-row locks and original field/reference contracts. No second table/ledger, arbitrary JSON paths or caller merges.

## New fixed interfaces

* `busy_owner_pending_review_v1(business,revision,enquiry)` — authenticated live owner, one exact Pending source, fixed source text/name/ID plus hash/revision/schema. No raw arrays, unknown fields, provider receipt, consent or mutation authority. Unsupported versions/media/stages, ambiguous or foreign records are denied. Original corrected contact/service values remain owner-reviewed Quick Capture fields alongside the retained source text.
* `busy_owner_manual_source_v1(business,revision,enquiry,text)` — only empty original customer/intake/Inbox history; creates one Pending text record labelled **Owner-supplied manual capture**, attributed to server UID. Server UTC queuedAt records registration, not an external customer-message event. Independent unknown root data is retained. This does not file a customer. No omitted field means deletion, no import/media/provider/financial provenance is accepted. Stable IDs are retained in exact receipts; stale/duplicate registration is refused. Fresh explicit owner creation is distinct from stale replay; no durable deletion/idempotency ledger is invented.
* Existing `busy_owner_first_enquiry_v1` — reviewed separately after source registration/current Pending review. Original customer/sourceRecords/activity/intakeLog/lifecycle/Filed identity construction, first-customer-only, exact current hash/revision. No existing-customer match or forced-new substitute. Phase65 corrects its JSON timestamps to the original millisecond-UTC `Z` format required by quote/private-reference validation and denies unsupported source versions. Historical Phase64 frozen evidence is retained, not rewritten.
* `busy_owner_first_reply_review_v1` — one original Filed Enquiry/customer with **absent** private reply. Fixed typed customer/enquiry allowlist plus exact hashes; unknown top-level/nested fields stay private. No versions, unsupported listing references, revoked contact preference, duplicate/foreign targets or existing/null/private reply replacement. Internal `initial_reply_context` is private, fixed-path, postgres-owned and non-executable by application/service roles.
* `busy_owner_reply_create_v1` — reviewed initial wording only; constructs the original version2/privateOnly/sourceStamp/reference/purpose=acknowledge record on server. Exact hashes, absence, membership and row revision checked inside the original lock boundary. Preserves unknown fields and all other targets. Fixed receipt includes target text/hash/source hash, IDs and revisions, not full source records. No send. Subsequent edits use existing v2 text operation, not creation or full replacement.

All public capabilities are postgres-owned SECURITY DEFINER with `pg_catalog,pg_temp` search_path, explicit live owner checks, revoked PUBLIC/anon/service EXECUTE and narrowly granted authenticated EXECUTE. Privileged owners/service inheritance/deployed bypasses still require real effective-ACL review. Mock UID is not Supabase JWT verification.

## Original client integration and boundaries

Original empty-workspace bootstrap offers capture without clearing device fields. Quick Capture preserves original field state and genuine public-setter typing epoch. A bounded filing hook owns only transient review/receipt status; businessSnapshotSession owns IO/tickets/uncertainty, original private adapter and reply hook/editor own preparation and wording. Source registration, filing, first reply preparation and first save require separate deliberate choices. No target receipt advances local global revision, applies customer arrays, clears unrelated dirty fields or confirms a device/whole-workspace save.

Source review tickets are process-local/one-use and bind identity, actor, workspace, view/epoch, exact source, corrections and local-payload stamp. Missing/foreign/stale/role-changed inputs fail safely. Changed typing (including edit/revert) invalidates approval. Confirmed creation uses metadata and target readback before repeat edit. Another eligible target needs fresh discovery/review; an old target's receipt is not transferable. Dropped acknowledgements remain unknown, without blind retry/fallback. A new session may observe committed data, never reconstruct an old own-operation receipt.

## Limits and next acceptance

Only text-only first Enquiry, no screenshots/AI/provider import/forced-new or existing customer matching. New account inputs are owner-supplied data, not authenticated historical catalogue/availability/booking/consent. `contactOk` default remains original app preference, not lawful marketing eligibility. Owner-recorded capture dates use explicit UTC context; real native/timezone presentation is not accepted yet.

The normal acknowledged path has local SQL + original parent coverage through registration→review→filing→first reply→save→fresh discovery/Open→edit/save. This is not a single browser-to-PostgREST or real-device test. Mid-flow interruption before a private reply exists still lacks bounded Pending/unsaved-Filed discovery. Lost registration/filing acknowledgements are unresolved; fields are kept and no retry occurs. No durable cross-device idempotency/process-death guarantee. Provider-origin/existing-customer workflows and other account domains remain separately gated/read-only under fences.

Cutover order: original provisioning/effective ACL provenance → narrow reviewed readers and finite writers → compatible client/service routes → legacy raw-read/full-write denial → isolated real owner/member/admin/revoked/foreign JWT/PostgREST tests, exposed helper/view/default/inherited grants, unknown retention/removal/concurrency/lost acknowledgements → actual browser/device acceptance → release review. No fence activation until legitimate domain/service paths are compatible. Services/notifications and all six Home areas retain existing limitations; no generic snapshot restore.

Rollback revokes the new four public capabilities; retain original row/data and both security fences. Do NOT restore broad raw reads, legacy full replacement or the old target-returning mutation RPC for old-client convenience.
