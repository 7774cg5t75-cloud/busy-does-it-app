# Provider connection transaction candidate — review only

This extends the two **original** social connection/state tables. It is not a new provider database or deployed API. Calendar provisioning authority is unavailable; calendar remains blocked. No existing endpoint imports the offline coordinator and both legacy provider/model denial fences remain intact.

Finite service-only operations prepare hashed state, atomically claim it, complete against the exact owner/business/connection revision, inspect secret-free original receipts and disconnect locally with CAS. Member-row locks serialise revocation; business-row locks serialise missing-row creation and per-business attempts. The claim commits before any simulated exchange, so uncertain/lost claims cannot replay. Replacing credentials never inherits refresh tokens or old assets. Disconnection invalidates pending claims and clears credentials without claiming provider-side revocation. State tombstones/receipts are retained; there is no automatic erasure schedule.

Use only disposable local PostgreSQL until a separate exact installation approval. Both install and retaining rollback contain explicit fuses. The installation revokes direct table/column grants from client/service roles and permits only five finite service functions. A table-owner-plus-finite-operation trigger protects business-bound rows from legacy direct service writers; a caller-set GUC alone grants nothing. A global or generic provider-enable flag is deliberately absent.

Activation blockers include authentic current hosted schema/owner/policy comparison, current server Auth/session and callback transport, provider-specific PKCE/nonce/code/userinfo verification, approved account replacement/review, canonical account deletion/retention, credential encryption/rotation policy and provider revocation/reconciliation. Existing token columns remain server-private, **not application-encrypted**. New Auth-user foreign keys require reviewed deletion/retention handling before installation. Current legacy status readers use raw service table access and must be migrated to the finite metadata projection before any hosted activation. No production DDL equivalence, live connection, independent security acceptance or spending approval is implied.

`rollback-retain.sql` revokes mutating RPCs, preserves all original/extended records and keeps only the scoped secret-free status reader. It does not resume unknown exchanges or restore legacy direct token access. Expired/unknown claims and credential erasure require independently reviewed reconciliation/retention; do not automatically retry or delete them.
