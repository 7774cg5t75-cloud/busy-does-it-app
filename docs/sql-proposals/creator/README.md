# Private Creator editing-state continuation — disabled local candidate

Not a hosted migration. The SQL and retaining rollback abort unconditionally. `CREATOR_DRAFT_ACCOUNT_ENABLED` stays false. No hosted installation, source disclosure, publication, provider, payment or booking authority is granted.

The original Creator editor, original local draft ID and Use/Keep/save ownership remain decisive. This subordinate private state cannot be safely packed into the original photo-required publishing queue: its rows lack complete private editing state/source relationships and may already be scheduled/published. Candidate heads use `(business_id, owner_id, draft_id)` with that original ID, and immutable versions carry independent revision/server operation UUID/request key/timestamp. No public queue status is changed. Existing queue IDs are denied rather than adopted. Publication interoperability, including concurrent handoff to the legacy queue, remains separately gated and is not production-ready.

Finite schema v1 stores text, brief, owner-reported facts, original prepared copy, social/poster/advert/newsletter wording format, treatment, channel selections, empty media and an owner-reviewed brand reference. Brand reference is historical metadata, not server-certified business facts. Unsupported media, story/caption variants and unknown private fields must stay in the original device record, not be silently discarded. This is a useful bounded text-only implementation, not complete migration of all Creator content. No CRM snapshots or arbitrary JSON keys.

A Growth association is optional. If present, its exact owner/business UUID, revision/hash and current reviewed permission are server-checked under the original Growth lock. Original provenance cannot be rebound during edit. Retirement permits historical inspection but denies saves; restriction denies full reads and excludes catalogue entries. Changed versions require a fresh deliberate source/new-draft path, not silent reassociation. Retention/deletion remain separate; immutable retention does not establish lawful erasure policy.

Finite RPCs: `busy_creator_draft_write_v1`, `read_v1`, `list_v1`, `operation_v1`. The original current business creator/owner authority is reused. Raw tables/private helpers have no client grants; fixed qualified privileged paths and effective table/schema checks remain. Only exact write responses are own receipts. Independent reads and exact uncertain-operation observations explicitly are not. Duplicate/stale writes fail atomically; the client consumes review tickets and blocks all queued writes after an uncertain outcome until exact observation succeeds.

Catalogue uses scoped keyset pagination over original draft IDs, 1–50 records per page, optionally exact opportunity UUID. No caption/name/date matching and no lifetime record limit. Summaries omit content. Full target reads independently recheck permissions. Source status and historical references stay distinct from preparation authority.

Upgrade/reapply is permitted only for marked postgres-owned proposal objects and rechecks effective grants. Untrusted existing schema/tables/functions fail; no takeover or data deletion. A separate deployment package/version review is still required before hosted installation. Retaining rollback replaces the writer with an unconditional denial body and revokes direct grants; records and source-checked reads remain.

Local verification uses approved PostgreSQL17 with `listen_addresses=''`, verified private socket/data directory, fictional auth.uid fixtures and original regression prerequisites. It does not establish JWT/PostgREST/native/provider acceptance. Original-component bridge is opt-in and excluded from the offline suite. No test authentication bypass is added to deployable SQL.


Schema v2 extends the same private draft identity with at most six ordered, explicitly reviewed references to the original `busy_website_original_media` registry. Current owner/business uploader, private Storage bucket/object, digest, MIME and size are rechecked on every full read and save. No new asset store or arbitrary URL authority is introduced. Missing/restricted originals return unavailable selections without paths; wording and history remain preserved. Actual bytes are read only through the original authenticated download gateway, which verifies their SHA-256 before returning them. Private review does not certify copyright, consent or public marketing rights.

The finite editor projection preserves up to six exact caption alternatives, selected caption ID (including deliberate deselection) and bounded privacy warnings. Stories and unknown editing fields are refused rather than dropped. Schema v1 text-only records remain unchanged; a v2 record cannot be downgraded by an older serializer. Explicit v2 media removal is revisioned and historical versions remain intact. The local runner exercises a genuine v1-package-to-v2 upgrade, reapply and retaining rollback.

`busy_creator_media_review_v1` provides a current exact original review, not a publication receipt. Publisher preparation is read-only and the original client payload builder refuses account-bound drafts pending a separately reviewed handoff. A server transaction into the legacy queue remains unsupported: its workspace key/email ownership does not establish the exact Creator business/owner UUID mapping. No global-ID trigger, provider submission or migration of legacy published/scheduled rows is included.
