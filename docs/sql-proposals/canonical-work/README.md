## Legacy private ownership gate

Legacy Work does not reliably identify its original private-wording author. Business membership is insufficient to adopt that text. Source review returns no legacy quote text/full-record hash, only a boolean indicating original Work. The migration function has NO authenticated/anon/service_role EXECUTE grant or application approval control. Only the local operator fixture tests retention/collision/atomicity with fictional known-owner data. Hosted backfill remains blocked until independently reviewed owner attribution and private-wording disclosure rules are encoded. Canonical created_by records canonical creation/migration authority, not historical authorship. An ordinary owner/co-owner cannot migrate another owner’s unknown private wording into their own scope. New canonical quotes/drafts use server-derived creators and creator-bound reads.

## Local-only immutable owner-report evidence — separate policy gate

The agreement evidence slice is disabled by CANONICAL_OWNER_REPORT_ENABLED=false in addition to the canonical account gate. Its sole supported class is owner_reported_offline/unverified: it never records verified acceptance or authorises booking. A creator-private immutable row binds exact quote revision, server-captured internal Prepared fields, whole Work-record/source fingerprints and original engagement/customer identity. Server recorded_at means when the owner report was recorded, never an invented external acceptance date. No Work notes/follow-up content is imported.

Four new finite agreement review/create/list/read RPCs use original owner/creator/source checks. Creation is append-only once per quote version; callers cannot set class/verification/time/terms JSON. Reads compare old captured terms to current quote but require current source/permission eligibility, return no original operation ID and cannot recover lost receipts. Rollback revokes create and denies fresh review while preserving records/read-only scope. All raw table/helper grants remain closed. This fused CREATE-only candidate is not an upgrade migration or permission to activate the proposed policy; retention/erasure/report-correction and real JWT/PostgREST acceptance remain gates.
