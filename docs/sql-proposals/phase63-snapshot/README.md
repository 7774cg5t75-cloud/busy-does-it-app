# Phase63 owner-only reply discovery — review candidate, not deployed

Requires original provisioning and Phase58/60 owner-private helpers/read fence. `busy_owner_reply_discover_v1(business,afterCustomerId)` derives auth.uid and live owner membership, then reuses the exact original owner_reply_context validator. Admin/member/service execution or private access is denied. Another owner's private reply is excluded even if the caller owns the business too.

The fixed response contains business/actor/revision/schema, at most25 items of customerId/enquiryId/customerName (name at most120 characters), hasMore and a stable-ID cursor. No wording, customer arrays, raw stamps, timestamps, unknown extensions or arbitrary JSON is returned. Discovery is recognition metadata, not an opening/save ticket. Duplicate/foreign/malformed/unsupported/stale-source entries are excluded; malformed collections and oversized source collections (>1000 customers or5000 enquiries) fail closed. Empty eligible results do not prove all drafts are absent. Source validation uses the same membership-before-row exclusive locks as the specialist; read-only discovery does not mutate a row. JSON array scan cost and lock duration require realistic staging performance acceptance.

A selected object is minted inside the existing account session. Inspection calls the original narrow review RPC at that exact discovered revision. Keep/Open belongs to the original reply hook. Open is one-use, and after any deferred original navigation review it rechecks the same record/source/hash/revision with the server. Typing, selected record, profile, scope, local source, revision and view changes invalidate approval. No account version replaces local customer/enquiry arrays or advances their revision.

The original editor opens only the reviewed wording and exact enquiry text in a transient account-only context. It names the account, hides legacy customer navigation, does not run ambiguous current-enquiry preparation and does not allow account/device saving from this recovery context. Local selected records, other business data, stored device drafts and unknown account fields stay untouched. A role/account change hides that context instead of falling through to legacy UI. This is session-only editing, not process-death or durable new-edit recovery.

All rollout switches and original production abort fuses remain disabled/intact. Rollback revokes discovery and retains both fences/data. The original narrow projection has its own existing rollback. Never restore raw JSON reads or full-payload mutation for compatibility. See combined Phase63 delivery report and initial-filing specification before any separately approved staging work.
