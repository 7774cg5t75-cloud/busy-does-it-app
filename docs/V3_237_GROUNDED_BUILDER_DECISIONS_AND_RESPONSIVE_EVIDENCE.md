# Busy Does It V3.237 — Grounded Cross-Builder Design Decisions and Multiwidth Evidence Gate

**Base:** V3.236 verified source commit e73bcbc6312b8277a90a1ad37ee4e5765c9d95d3, plus the later source-equivalent Snack-only metadata commit 854e74e32444bcd3e162c24b6b314b0b52dc1e37.
**Product references:** GitHub technical master; accessible Word master V22.17 visual design-agent requirement, and GitHub-recorded V22.18 Business Brain/Work refinement. The owner has not approved a real hosted deployment, paid native build or autonomous customer-facing edits.

## Why this sweep
V3.236 already shares one next safe step and two distinct design directions across the original Website Builder and Business App Builder. The directions were generic planning text and could not explain why to inspect one first, where the website and app currently disagree, or whether any actual responsive design comparison is supported. Adding new visual "AI scores" without real screenshots would mislead owners.

## Source changes
1. **Grounded, explainable first-review priority.** New \`sharedBuilderDesignDecisionV3237.mjs\` consumes the **existing** V3.210 universal capability statuses and V3.236 plan/revision guards. It proposes reviewing "make the customer task easier" first only where a requested action is actually present in that surface's private draft and no blocked requested capability exists. Otherwise it recommends "make the business clearer" first. This is a **planning priority, NOT a visual quality winner**. Every capability remains unverified as a live customer outcome.
2. **Website–App cross-check.** Bounded alignment notes show requested capabilities whose status differs between the website draft and Business App draft. These are descriptive observations, not automatic mirroring of functionality. The comparison omits owner-locked element names and business media. It only compares explicit custom HEX accents when both surfaces supply them; different accents are a potential intentional native adaptation, never an automatic defect.
3. **Coordinated component checks.** Each V3.236 direction now has a bounded grouped review checklist (hierarchy, whitespace, brand continuity and readable content vs first action, navigation, support content and permissions), blockers and an explicit trade-off. Nothing is applied. The single pre-existing opt-in comparison disclosure in \`universalBuilderPlanReview.js\` now explains the reason, not a fabricated design score. This inherited screen is already used by BOTH builders.
4. **Fail-closed source-bound responsive evidence evaluator.** New \`sharedBuilderMultiwidthEvidenceV3237.mjs\` extends the EXISTING \`compareWebsiteVisualReports\` measured-DOM policy. Future reports must name the exact tenant, original website ID, generation, enabled page, three **distinct** phone/tablet/desktop widths and matched baseline/candidate counters. New warnings at **any** width block a positive owner-review recommendation; improvements with no known measured regressions permit **review only**. The module does not capture screenshots, authenticate caller provenance, test native apps, modify design, certify accessibility or authorise publishing.
5. **Safety and regression harness.** New offline V3.237 assertion script exercises private-draft priorities, owner locks, cross-builder mismatch, explicit accent tokens, unknown features, mismatched tenants/generations, missing or manipulated viewports, missing reports and the no-execution contract. A dedicated V3.237 GitHub Actions workflow inherits the previous V3.236 quality/regression checks plus the two disposable PostgreSQL CI jobs. Source CI proof must be checked after the final committed revision.

## Known limits
- No two real rendered alternatives or screenshot evidence from this sweep. The new future-gate tests use synthetic fixtures and **do not** count as successful physical-device inspection.
- No customer booking, payment, message delivery, native app delivery, provider fee or subscriber outcome was tested live. Hosted staging has not been migrated/updated.
- No new SQL migration, no publishing, no remote code generator, no business-to-business transfer or AI model retraining.
- Current private layouts are only assessed through limited structural facts; colour consistency does not prove legibility. The owner retains ultimate visual and functional approval.
- Later authorised staging work should connect actual *version-matched* original and candidate render measurements to this evidence gate, capture real screenshots at several widths, and run customer task completion checks before any real rollout.

**North-star:** More useful intelligence beneath one simple interface; reusable original builders, reliable outcomes and minimal user effort — not artificially impressive test counts or made-up results.
