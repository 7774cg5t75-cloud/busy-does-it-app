# V3.122 — private Business Brain, bounded recovery and honest operations

## What was implemented

1. **True publish/recovery permission in shared website state.** The publishing view now requires that the private draft has not changed since the current hosted preview before setting canPublish. It denies client-invited manual recovery when an existing automatic recovery process is already working. The Website Publishing screen retains the V3.121 exact-hosted-preview owner click and independent server approval requirements.
2. **Bounded status self-recovery rather than uncontrolled mutation.** Added a pure policy contract that allows at most one transient retry of three explicitly enumerated read-only sources: website health, provider status and restricted founder aggregate reporting. No arbitrary source or retry-after-quota response is whitelisted. Website publishing, rollback, DNS edits, domain purchase, social posting, customer data writes, subscriptions, paid AI generation, notifications and bookings are always excluded. The new contract decides only; it does not execute a network call, create a job or mutate external state. The older guarded read-only recovery implementation remains responsible for any permitted real status reads.
3. **Business Brain style advice without false learning claims.** Rejected visual styles are now identified honestly as previously rejected, instead of receiving a generic industry-based recommendation. The current Website Builder displays that warning beside the style. Its feedback labels explicitly refer to the **current private website**, removing confusion with an alternative shown alongside it. No other business's style data may be used, and there is no foundation-model retraining or verified conversion uplift.
4. **Visual website reviewer.** Browser-measured website review guidance now explicitly marks whether a candidate can be suggested *as a private draft*, whether evidence is missing or a candidate is a measured regression. The reviewer cannot apply its suggestions or publish; it does not claim an AI has judged visual beauty, or that traffic, sales or enquiries increased.
5. **Founder safe-automation summary.** Founder Operations now explains which limited status rechecks can be retried and which state-changing actions require independent authorisation. Its counts come only from the verified founder-only aggregate snapshot; stale, unknown or unauthorized reports do not authorise automation, report known revenue or mean there are no problems.

## Testing
The dedicated V3.122 workflow executes the new policy tests, previous V3.121–V3.117 regressions, Expo iOS JavaScript compilation, 18 Chromium views from nine fictional businesses, before/after website editing, five-industry design variety, first-fold screenshot provenance and obscured-call-to-action checks, responsive layout at five widths and keyboard accessibility.

This is **GitHub development code** and fictional-browser testing. It is **not** a signed iPhone build, real customer pilot, proof of deployed self-healing, registered domain, live website, activated screenshot AI model or production data migration. No paid supplier requests, DNS changes, automatic publishing, customer data sharing or other externally visible effects were performed.
