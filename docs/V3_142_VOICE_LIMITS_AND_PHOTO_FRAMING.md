# Busy Does It V3.142 — Pause-safe voice, visible limits and whole-photo control

## Goal
Customers decide when they have finished speaking. BUSY **must not stop on silence**, including a long pause while thinking. The editor must also show when a microphone is active, guard against a forgotten recording and avoid surprise cloud-transcription costs. Keep the front end plain language and optional.

## Implemented in the V3.142 development source
- `src/screens/websiteSelectedVoice.js`: deliberately separate steps **Record → Stop → Review recording → Send for transcription** or **Discard**. A stop NEVER uploads automatically. Silence/pause detection is not used. A prominent MM:SS timer is visible throughout recording. A warning appears in the last minute before the disclosed **5-minute safety cap**. At the limit, the recorder is locally stopped and the file is saved for a separately initiated send/discard — **nothing is uploaded without pressing Send**. Closing the editor cleans up active recording and does not transmit or publish.
- `src/core/websiteVoiceRecordingPolicy.mjs`: shared finite duration, timer and audio-size budget helpers. An explicit 9MB maximum upload protects against unexpectedly long media; iOS/Android native recording behaviour still needs physical-device acceptance.
- `supabase/functions/busy-command/index.ts`: authenticated selected-element **transcription-only** operation (no Operator action planning). Strict 9MB limit, verifies identity and atomically reserves usage before calling the paid transcription provider. On exhaustion, explains the limit and tells the owner to type instead. Fails closed if the database budget migration has not been applied; no unmetered fallback.
- `supabase/migrations/20261011120000_busy_website_voice_usage.sql`: private service-role-only daily counter with atomic reservations, maximum **12 selected-website voice requests per signed-in owner per UTC day**. No recording, transcript, personal website text or selection is stored in the counter. Each request reserves an attempt before transcription; failed provider processing may still count toward the request ceiling because the reservation exists to prevent abuse. This is a **technical usage ceiling**, not a final pricing/credits plan.
- The app receives and validates the remaining allowance and the voice control reports it after transcription. Typed and one-tap local edits do not use paid voice transcription.
- `websiteLayoutEditing.mjs`, the native tap editor and contextual grammar: **Show entire photograph** or **Fill photo tile**, as independent, safe per-gallery-image framing choices. These coexist with the selected photo's top/centre/bottom focal preference. HTML/CSS is fixed allowlisted tokens, never owner-submitted CSS.
- Private/ZIP and hosted website renderers share photo-fit classes via the `designSystem.mjs` stylesheet, with exact approved-image choices preserved across factual website regeneration.

## Safety and verification
- The legacy app-wide Talk to BUSY voice button remains unchanged; this sweep improves the **selected website element** microphone workflow specifically.
- Selected voice never publishes, executes a generated command or edits a live website automatically. The customer explicitly reviews the transcription, then separately applies the validated private-draft change with Undo/Redo.
- `scripts/check-website-voice-reliability-v3142.mjs` tests timer boundaries, upload limits, no silence-stop or automatic upload, SQL permission and atomic quota contracts, exact image fit targeting and private/hosted parity.
- `.github/workflows/website-voice-reliability-v3142.yml` tests previous website regressions, Deno Edge Function typechecking, mobile/tablet/desktop Chromium and unsigned iOS/Android Expo JavaScript bundles. Keep the new regression in general production CI.
