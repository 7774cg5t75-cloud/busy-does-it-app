# V3.115 four-area implementation

## Website review
Mobile and desktop screenshot assessments gain explicit checks for whether the primary call to action exists, is visible and is reachable. The shared comparison rejects missing, hidden or disconnected buttons and requires comparable measurements on both versions. Real Chromium runs on fictional business websites and deliberately hides an action to ensure the reviewer rejects it. This is automated quality evidence, not a live multimodal AI designer.

## Business Brain learning foundation
A new owner-initiated, per-business design feedback route saves a minimal liked/rejected visual-family choice. No website copy, photographs, customer data, prompt history or private page content is written. Authenticated owner/admin membership is enforced for append, read and clear; database access is service-role-only with RLS and per-business idempotency. An owner can clear all saved preferences; style recommendations prefer liked styles and push away rejected ones when safe. A DB constraint forces aggregate consent false, and there is NO cross-business learning, model retraining or global data export.

The feedback migration and server handler are source-only until separately reviewed and deployed to Supabase. The functionality cannot be claimed live on the installed app from a CI pass.

## Domain setup
Website Management now explains the correct next step for BUSY-provided, customer-owned and future purchased domains from actual known connection status. A hostname recorded in the database does not count as an externally verified live site. Domain checkout and automatic renewals remain disabled until a real registrar agreement, payment/registrant verification and transparent pricing are implemented.

## Founder evidence
Founder-only cloud usage records are now labelled with recent read-only provider readings versus manual or missing measurements. The dashboard makes no GBP totals or invoice claims based on log samples, supplier traffic readings or estimates.

## Verification and next step
Unit and integration tests validate the four tracks, enforce feedback data minimization and provider provenance, and rerun prior regression suites. An iPhone JavaScript export and browser audits of original and edited fictional sites exercise mobile and desktop layouts, accessibility, and genuine design diversity. All workflows are development-only: no paid calls, DNS changes, live websites, Supabase migration deployment or signed native iOS build.

Next: inspect and safely deploy the feedback migration with owner approval, evaluate a genuine paid visual-review sandbox with explicit per-review metering, and pursue registrar reseller onboarding once legal/commercial terms are suitable.
