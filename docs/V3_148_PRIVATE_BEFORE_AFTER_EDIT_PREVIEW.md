# Busy Does It V3.148 — Preview selected voice/text changes before saving

## Coordinated areas improved

1. **Intuitive owner experience:** the selected-element panel now offers an optional **“See these changes before saving”** action. BUSY shows a private on-device visual preview of the exact selected page, with a single toggle between **Show original website** and **Show proposed changes**. The owner can still use the existing one-Undo **Apply** flow or close without saving. We reuse the floating toolbar, scoped microphone, contextual instruction parser and existing website renderer, not a second editing engine.

2. **Safe multi-part instructions:** a preview is generated by re-parsing the owner's actual typed or transcribed words against the current site, page, section, item, photo index and revision. The exact V3.147 all-or-nothing domain transaction runs on a temporary immutable candidate. If step two fails, nothing is previewed or changed. Apply is still independently re-parsed at the time of approval. A new security guard rejects non-photo selections with forged photo indices. The original website revision, Undo/Redo and publishing status remain unaffected by requesting a preview.

3. **Photo framing UX:** fixed an issue in the existing design controls where a gallery image's **“Show the entire photograph” vs “Fill the tile”** selection incorrectly used its crop position when deciding which option had the checkmark. The checked state now reads the specific selected picture and field rather than the entire section. Owner-approved photos, private draft boundaries and gallery undo remain unchanged.

4. **Responsive review and code health:** the preview WebView uses static HTML **with JavaScript disabled**, no editor bridge or DOM selection script, no file access and blocked external navigation. It is explicitly labelled as a local-width preview rather than a design-quality score. Dedicated real Chromium checks exercise original versus candidate at 320, 390, 768 and 1440 pixels, alongside V3.138–V3.147 website, voice, touch accessibility, business preference and visual-measurement regressions, unsigned Expo iOS and Android JavaScript exports. Production foundation CI permanently tests the new selection/preview safety rules.

## Intentional limitations and next steps

A customer may choose to preview changes, but previewing is **not mandatory** for every quick edit. It never auto-publishes, auto-spends credits, generates a model response or sends selected business content to a paid provider. All edits remain private until separately approved and published. Responsive screenshots and static browser checks cannot replace a signed real-device acceptance test or a hosted website preview. Staging deployment of the selected-element transcription mode and the per-owner voice-usage migration is still required before true voice-to-edit end-to-end testing.

Keep future coordinated sweeps focused on this single user interaction: select the element, optionally speak, review the precise result, accept or undo. Reuse the same pattern in the app builder rather than building unrelated menu-heavy editing workflows.
